# 动态助手目录

## 实现范围

Hub Manager 管理助手的名称、图标、介绍、能力、使用条件、创建文案、排序和上下架；小程序从接口读取目录，复用同一套详情、创建、微信连接和换绑页面。“我的”从服务端读取当前用户的助手实例，不在客户端枚举助手类型。

- 助手 ID 是稳定业务标识。所有助手的 ID 在新建时根据名称生成。
- 创建发送 `agentId`；Hub 负责映射部署好的 Hymatrix 模块。客户端不传模块、脚本或服务端执行代码。
- 当前每个用户每类助手保留一个当前实例，沿用原有防重复创建规则；列表返回每类最新任务。
- 下架仅从助手广场隐藏，不停止实例、不删除账号资料；任何用户仍可直接访问详情、登录创建或管理已有连接。
- 有用户记录的助手不可删除。无记录且已下架的自定义助手可删除。
- 创建时保存模块和名称快照，之后修改目录不改变已创建实例的模块。

## 接口

- `GET /v1/wechat/catalog`：公开的已上架目录，按排序及 ID 排序。
- `GET /v1/wechat/catalog/:id`：公开详情；下架后仍可通过 ID 直接访问，不要求已有创建记录。
- `GET /v1/wechat/agents`：当前登录用户的助手列表，包括下架助手；不返回二维码或模块信息。
- `POST /v1/wechat/agents/spawn`：`{"agentId":"third-agent"}`；仅接受 `agentId` 标识助手。
- current、状态、连接码和换绑接口用于通用实例管理；实例 ID 由后端校验归属。

## 上线顺序

1. 先部署对应 Hub 分支。启动仅创建目录表，不自动插入任何助手，不导入旧配置。
2. 在 Hub Manager `/admin/agents` 手动创建助手、上传图片、填写文案和已部署模块；所有助手使用相同规则。
3. 用小程序体验版验证列表、登录创建、已有助手恢复、连接码保存及换绑。
4. 上传并审核发布新版小程序。前后端使用统一的 `agentId` 协议，不支持旧版 `template` 参数或页面链接。
5. 后续新增同一交互流程的助手时，仅需在后台配置。新的交互或服务范围仍需单独评估更新和审核。

图标在 Manager 编辑器中上传（PNG/JPEG，最多 5 MB、4096 × 4096），图片保存在 Manager 数据库，经 `/v1/wechat/catalog-images/:id` 公开读取。小程序根据当前后端地址补全图片 URL；正式环境使用 HTTPS。二维码卡片自动使用助手名称。

## 验证

在小程序项目内运行 `node --test tests/*.test.js`。真机仍需验证新助手的实际后端模块、微信扫码和相册权限；自动化测试不代表已完成线上部署或微信审核。

## Hub 本地验证

`go test ./...`；数据库集成测试通过 `HUB_TEST_POSTGRES_DSN` 指向独立 PostgreSQL 数据库，执行 `go test ./manager -run TestCatalog -count=1`。不要指向生产数据库。

本版创建流程仍使用既有 Hermes / Hymatrix / 微信连接协议。新助手模块须遵守同一运行时协议；不同运行时需另行实现服务端适配。

## 可视化编辑

直接在广场卡片中编辑名称、列表介绍，在详情画面中编辑详细说明、能力、使用条件和创建按钮文案；画面同步更新。模块、排序、上架状态位于运行设置。新建时省略 ID，后端根据名称生成稳定 ID；同名冲突会提示，改名不改变已有 ID。图片上传需管理员登录，读取无需登录；相同图片按内容去重，删除助手不删除图片。
